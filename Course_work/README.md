# Індикатор рівня звуку

Курсовий проєкт, тема 3, варіант Р: передача відліків через регістри AXI4-Lite.

## Архітектура

Програма на C → MicroBlaze → AXI4-Lite → власний IP, модуль `sound_level_estimator`.

AXI4-Lite інтерфейс, регістри й алгоритм об'єднані в одному модулі
[sound_level_estimator.sv](sound_level_indicator/sound_level_indicator.srcs/sources_1/new/sound_level_estimator.sv).
Зовнішні порти: `clk`, `reset_n`, п'ять каналів AXI4-Lite та `level[3:0]`.
`sample_write`, `sample_value`, `window_size` і `peak` є внутрішніми сигналами.

Для пакування використовується тонка Verilog-обгортка
[sound_level_estimator_ip.v](sound_level_indicator/sound_level_indicator.srcs/sources_1/new/sound_level_estimator_ip.v), яка лише з'єднує порти
з наявним модулем SystemVerilog. IP Packager вимагає Verilog або VHDL на верхньому рівні.
Верхній модуль для синтезу та пакування — `sound_level_estimator_ip`.
Верхній модуль симуляції — `tb_sound_level_estimator`.

Кожен запис у `IN` передає один 16-бітний знаковий відлік і виконує один крок
алгоритму. Модуль зберігає історію восьми останніх відліків у регістрах,
визначає найбільший модуль серед останніх `N` відліків і формує рівень 0–8.
Пошук максимуму реалізовано комбінаційним деревом. Запис `N` одразу змінює
результат дерева, а сама історія зберігається.
Усі частини IP працюють від одного тактового сигналу. Вихід `level[3:0]`
дорівнює значенню регістра `LEVEL`.

## Регістри

Усі регістри 32-бітні; зсуви відлічуються від базової адреси IP в Address Editor.
Невикористані старші розряди при читанні дорівнюють нулю.

| Зсув | Назва | Доступ | Значущі розряди | Призначення |
|---|---|---|---|---|
| `0x00` | `IN` | Запис | `[15:0]` | Знаковий відлік −32768…32767; кожен запис запускає один крок |
| `0x04` | `N` | Запис/читання | `[3:0]` | Розмір вікна: 1–8 |
| `0x08` | `PEAK` | Читання | `[15:0]` | Максимум модуля відліку: 0–32768, без знака |
| `0x0C` | `LEVEL` | Читання | `[3:0]` | Поточний рівень: 0–8 |


## Обрані правила реалізації

Ці правила уточнюють поведінку, яку технічне завдання не задає однозначно.

- Після reset: `N = 4`, історія очищена, `PEAK = 0`, `LEVEL = 0`.
- До заповнення вікна використовуються наявні відліки; порожні місця містять нулі.
- Історія завжди містить до восьми останніх відліків незалежно від `N`.
- Запис у `N` не додає відлік і не очищає історію. Пік і рівень перераховуються
  за новим розміром вікна без очікування наступного запису в `IN`.
- Після збільшення `N` знову враховуються старіші відліки, якщо вони ще є в історії.
- Недопустимі значення `N` обмежуються: 0 → 1, значення більше 8 → 8.
- Модуль відліку зберігається без знака: `abs(-32768) = 32768`.
- Обрано варіант 4: `LEVEL = floor(PEAK / 4096)`, тобто `PEAK >> 12`.
  Для 16-бітного беззнакового піка це вибір чотирьох старших бітів `PEAK[15:12]`.
  Рівні 0–7 відповідають діапазонам по 4096 значень. Рівень 8 досягається
  лише при `PEAK = 32768`; це явно обрана поведінка шкали.


| PEAK | LEVEL |
|---|---|
| 0–4095 | 0 |
| 4096–8191 | 1 |
| 8192–12287 | 2 |
| 12288–16383 | 3 |
| 16384–20479 | 4 |
| 20480–24575 | 5 |
| 24576–28671 | 6 |
| 28672–32767 | 7 |
| 32768 | 8 |

## Очікувані результати до запуску симуляції

Кожен незалежний сценарій починається зі скидання, потім запису потрібного `N`.
Після кожного відліку тестбенч має прочитати й перевірити `PEAK` та `LEVEL`.
Значення нижче визначені прямим переглядом останніх `N` абсолютних значень
і діленням піка на 4096 з округленням вниз.

### Сценарій 1: вікно N = 4

| Вхідний відлік | PEAK | LEVEL |
|---|---|---|
| 100 | 100 | 0 |
| −300 | 300 | 0 |
| 50 | 300 | 0 |
| 20 | 300 | 0 |
| 10 | 300 | 0 |
| 5 | 50 | 0 |

Після останнього відліку вікно містить `[50, 20, 10, 5]`;
відлік −300 вже вийшов із вікна, тому пік зменшується до 50.

### Сценарій 2: N = 1 і граничні знакові значення

| Вхідний відлік | PEAK | LEVEL |
|---|---|---|
| 32767 | 32767 | 7 |
| −32768 | 32768 | 8 |

У вікні один відлік, тому пік дорівнює модулю поточного числа.
Другий запис перевіряє, що 32768 не інтерпретується як від'ємне число.

### Сценарій 3: вікно N = 3

| Вхідний відлік | PEAK | LEVEL |
|---|---|---|
| 0 | 0 | 0 |
| 16384 | 16384 | 4 |
| 32767 | 32767 | 7 |
| 16384 | 32767 | 7 |
| 0 | 32767 | 7 |
| −16384 | 16384 | 4 |
| −32768 | 32768 | 8 |

Перед останнім відліком вікно містить `[16384, 0, -16384]` і має пік 16384.

## Проблеми та розв'язання

1. **Пакування SystemVerilog.** Додано Verilog-обгортку `sound_level_estimator_ip.v`
   для верхнього рівня IP Packager.
2. **Дублікати й застарілі шляхи у File Groups.** Залишено актуальні джерела
   в каталозі IP та виконано повторне пакування.
3. **Від'ємний WNS на 100 МГц.** Пошук максимуму замінено деревом, додано
   регістр маски й встановлено 90 МГц; отримано WNS +0,202 нс.
4. **Невідповідність частот IP і Clocking Wizard.** Параметр `FREQ_HZ`
   змінено на 90000000, IP повторно упаковано й оновлено в Block Design.
